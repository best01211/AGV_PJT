# Base 실시간 다점 보정 적용

## 적용한 변경

실시간 worker를 공식 Hypersim Metric **Base(ViT-B), 입력 294**로 변경했습니다. 기존 Small 값에 새 계수를 곱하지 않습니다. 원본 RGB의 렌즈 보정과 중앙 20×20 ROI 정의는 그대로 유지합니다.

기록된 나무색 벽 7점으로 만든 중앙 거리 실험식:

```text
중앙 시험 보정값(m) = Base 원본 중앙값 × 0.5248586890 - 0.4192171250
```

적용할 원본 추정값 범위는 약 1.433~3.158m이며, 실측 자료는 0.3~1.2m입니다. 범위 밖은 외삽하거나 최솟값으로 잘라 표시하지 않고 ‘보정 범위 밖’을 반환합니다. 다른 모델·입력 크기에 적용하지 않습니다. 이 식은 **같은 나무색 벽 장면의 중앙값에만 근거**가 있고 물체 전체 픽셀 깊이에 적용하지 않습니다.

## 검증과 한계

| 후보 | 7점 중 한 점씩 제외한 평균 오차 | 최대 오차 |
|---|---|---|
| 1차식 | 약 5.1cm | 약 9.6cm |
| 2차식 | 약 5.3cm | 약 14.2cm |

1차식을 선택했습니다. 7점 모두에 적합한 평균 오차 약 3.4cm는 학습 자료상의 수치이며 별도 검증 성과가 아닙니다. 모델과 식을 이 자료를 보고 선택했으므로 교차검사 역시 새로운 물체의 정확도 보장이 아닙니다.

이전 4점 보정식으로 새 3점을 평가한 보고서는 `DEPTH_VALIDATION_20261103.md`에 그대로 보존합니다. 현재 식은 7점 전체를 사용한 새 버전이므로 그 3점을 다시 독립 시험 자료라고 부르지 않습니다.

현재 자료만으로 집기에 충분하다고 판단할 수 없어 `usable_for_grasp=false`와 `usable_for_control=false`를 유지합니다. 손가락/집게 좌표, 물체 검출·영역 분할, 카메라 외부 보정이나 로봇팔 구동은 추가하지 않았습니다. 사용자가 요청한 Depth 보정에만 적용했습니다.

## 화면과 기록

`/video`를 새로고침하면 Base 원본 거리와 중앙 시험 보정 거리가 별도로 표시됩니다. 색상 지도는 원본 Base 출력입니다. 보정 거리가 전체 픽셀에 유효하다는 인상을 주지 않도록 dense 배열은 변환하지 않습니다.

새 기록은 `data/depth_evaluation/measurements_v2.csv`에 저장합니다. 기존 Small 기록 `measurements.csv`는 수정하지 않습니다. 새 CSV에는 원본 prediction_m, encoder, input_size, profile_id, corrected_center_m을 함께 기록합니다. NPZ에도 모델명·입력 크기·프로파일·보정 중앙값을 포함합니다. `depth.benchmark`는 기본 measurements.csv를 읽을 때 v2 기록도 함께 읽어 같은 원본 RGB 조건에서 재추론할 수 있습니다.

## 재현 및 테스트

```powershell
.\.depth-venv\Scripts\python -m depth.tune_profile --predictions data/depth_comparison/20261103_validation/predictions.csv --output config/depth_runtime_profile.json
.\scripts\start-video.ps1
```

웹 서버 회귀 테스트 54개와 보정·후처리 테스트 4개가 통과했습니다. 프로파일은 `config/depth_runtime_profile.json`입니다. 기존 4점 프로파일은 변경하지 않았습니다.

## 정확한 집기를 위한 남은 검증

다음 검증은 같은 벽의 값을 더 정밀하게 맞추는 것이 아니라, **실제 집을 물체가 ROI를 채우는 장면에서 새로 측정한 거리**에 현재 고정된 식을 적용하는 것입니다. 물체가 ROI 일부만 차지하면 배경의 깊이가 섞이므로 현재 중앙값을 물체 거리로 해석하면 안 됩니다. 새로운 대상의 오차가 허용 수준을 넘으면 장면별 스칼라 보정으로 충분하다고 볼 수 없습니다.
