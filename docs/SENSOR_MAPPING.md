# 실제 센서 기반 2D 지도 생성

## 구현 범위

실제 거리와 외부 위치 추정값을 받아 2D 점유 증거 지도를 생성하는 모듈, FastAPI 입력 API, 웹 표시 및 파일 저장을 구현했습니다. Mock 주행 좌표와 연결하지 않았습니다. GPIO·시리얼·카메라 프로토콜은 임의로 정하지 않았으며 실제 장치 수집 어댑터와 ArUco 위치 추정기는 아직 연결되지 않았습니다. 현재 구현이 실측 지도 정확도를 입증하거나 자율주행 가능 여부를 보증하지 않습니다.

상대 깊이 영상을 미터 단위 거리로 사용하는 입력도 제공하지 않습니다. Depth Anything은 모델 종류·카메라 보정·거리 오차를 검증한 후 별도 투영 모듈로 추가해야 합니다.

## 1. 실행

프로젝트 루트에서:

```powershell
.\.venv\Scripts\python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

http://127.0.0.1:8000/mapping 에 접속합니다. 화면은 가상 탐색을 일시정지한 상태에서 열립니다. **탐색 재개**를 누르면 관측 영역과 경로가 늘어나고, **처음부터**를 누르면 가상 탐색을 처음부터 재생합니다. **실측 관측**으로 전환하면 별도의 실측 지도와 최신 센서·위치 입력을 표시합니다. 관측 면적 비율은 값이 기록된 셀 수를 전체 격자 셀 수로 나눈 값이며, 불확실한 셀도 포함합니다.

`/` 주행 화면 상단에서도 관제를 열 수 있습니다. API 상세는 `/docs`입니다. 단일 프로세스/worker로 사용합니다. 인증이 없는 개발용 API이며 원격 공개를 전제로 하지 않습니다.

## 2. 좌표와 시간 계약

- 모든 거리와 좌표: m. 각도: rad. x는 전방, y는 좌측인 로봇 기준을 사용합니다. 지도에서 yaw=0은 +X, 양수는 반시계 방향입니다.
- 지도 원점은 왼쪽 아래입니다. 내부 배열은 `row * cols + col`, row=0은 아래쪽입니다. 웹 표시 시 위아래를 반전합니다.
- 외부 위치 추정기는 로봇 본체 기준점의 위치를 반환해야 합니다. 카메라 위치를 그대로 입력하면 안 됩니다.
- `frame_id`는 위치 추정과 지도에서 동일해야 합니다.
- `timestamp_s`는 초 단위 Unix epoch입니다. ESP32의 uptime/millis를 그대로 입력하면 안 됩니다. 보드와 호스트의 시간 기준을 변환하거나, 측정 시각의 오차를 한정한 수집기를 구현해야 합니다.
- 위치와 측정의 시각 차이는 기본 0.1초 이하, 데이터 나이는 기본 1초 이하, 미래 시각 허용 오차는 0.1초입니다. 설정은 실제 지연·주행 속도에 맞춰 검증합니다.
- `valid`, `confidence`, 표준편차는 입력자가 실제 근거를 갖고 계산해야 합니다. 고정된 높은 신뢰도로 검사를 우회하지 않습니다.

## 3. 실제 장착값 입력

`config/mapping.template.json`을 복사해 작업 설정을 만듭니다. 센서 배열은 의도적으로 비워 두었으며 그대로는 초기화할 수 없습니다. 크기와 한계값도 초안이므로 시험 공간과 장비에 맞춰 수정합니다.

각 센서에 다음을 등록합니다.

| 필드 | 값의 근거 |
|---|---|
| sensor_id | 수집 프로그램과 일치하는 고유 ID |
| x_m, y_m | 로봇 기준점에서 센서까지 실측한 위치 |
| yaw_rad | 로봇 전방 기준 센서 방향 |
| fov_rad | 전체 감지각. 설치 조건을 반영해 검증 |
| min_range_m, max_range_m | 유효 반사가 확인된 사용 거리 범위 |
| range_sigma_m | 고정 표적 반복 측정으로 추정한 거리 표준편차 |

입력 구조 예시(값을 모두 실측값으로 교체):

```text
{"sensor_id":"front","x_m":<장착 X>,"y_m":<장착 Y>,
 "yaw_rad":<방향>,"fov_rad":<전체 감지각>,
 "min_range_m":<최소 유효 거리>,"max_range_m":<최대 유효 거리>,
 "range_sigma_m":<거리 표준편차>}
```

화면의 JSON 설정란에 넣고 ‘빈 지도 생성’을 누릅니다. 처음에는 모두 미탐색입니다. 최대 40,000셀까지 허용하며 가로/세로 길이는 해상도의 정수배여야 합니다. 기존 지도를 교체할 때는 ‘현재 지도 초기화’를 명시적으로 사용합니다.

방향별 거리 카드에는 `front`, `rear`, `left`, `right` ID의 최근 수락 반사가 표시됩니다. 지도 위의 부채꼴은 관측 시점의 장착 방향과 거리를 보여주며, 오래된 반사는 숨깁니다. 최근 수락 위치의 궤적은 최대 1,500개 지점을 표시하고, 위치 입력 간격이 `max_age_s`보다 길어지면 선을 끊습니다.

전면 A 영상은 기존 `JETANK_CAMERA_URL`과 `JETANK_CAMERA_FORMAT` 설정을 사용합니다. 전면 B는 `JETANK_SECONDARY_CAMERA_URL`과 `JETANK_SECONDARY_CAMERA_FORMAT`을 별도로 설정합니다. 형식은 `mjpeg` 또는 `snapshot`이며, 서버를 다시 시작한 뒤 각 채널의 **영상 연결**을 누릅니다.

실측 화면에서 카메라 시야를 표시하려면 `MapConfig.camera_views`에 채널 `a`, `b`별 `channel`, `x_m`, `y_m`, `yaw_rad`, `fov_rad`, `max_range_m`을 넣습니다. 수치는 실측 장착 위치, 수평 시야각, 표시할 거리 범위를 사용합니다. 이 시야는 위치에 맞춰 그리는 도형이며, 현재 영상 픽셀로 점유 증거를 갱신하는 처리는 별도입니다.

## 4. 센서·위치 프로그램에서 보내는 데이터

`POST /api/mapping/observations`

아래 수치는 **입력 형식 설명용**이며 하드웨어 기본값이나 실측 기록이 아닙니다. timestamp는 매번 실제 관측 시각으로, 위치와 오차는 실제 추정 결과로 교체합니다.

```json
{
  "pose": {
    "frame_id": "map",
    "timestamp_s": 1793600000.0,
    "x_m": 1.0,
    "y_m": 1.0,
    "yaw_rad": 0.0,
    "valid": true,
    "confidence": 0.9,
    "position_std_m": 0.03,
    "yaw_std_rad": 0.03,
    "source": "external_measured"
  },
  "measurements": [
    {
      "sensor_id": "front",
      "timestamp_s": 1793600000.0,
      "distance_m": 1.2,
      "valid": true,
      "return_type": "echo",
      "source": "hardware"
    }
  ]
}
```

위치 source는 `aruco`, `odometry`, `fused`, `external_measured`만 허용합니다. 아직 위치 추정기가 없다면 알려진 위치·방향에 로봇을 정지시키고 측정한 기준점에서 정적 관측부터 수집할 수 있습니다. 이동 후에도 같은 위치를 입력하면 잘못된 지도가 됩니다. `external_measured`라는 문자열 자체가 실제 측정 여부를 증명하지는 않습니다.

초음파 source는 `hardware` 또는 `recorded`. 무응답은 `valid:false`, `return_type:"no_echo"`, `distance_m:null`로 전달합니다. `echo`는 유효 반사가 있었을 때만 사용합니다. 순차 측정 센서는 각자의 측정 시각을 사용하고, 시간 차이가 커지면 각각 맞는 위치로 별도 요청을 보내야 합니다. 한 요청의 단일 pose를 오래된 네 센서 값에 공유하지 않습니다.

수집 프로그램이 한 줄에 하나의 위 JSON 객체를 출력한다면 다음 전달 도구를 사용할 수 있습니다.

```powershell
.\.venv\Scripts\python -m mapping.ingest_jsonl --input - --url http://127.0.0.1:8000/api/mapping/observations
```

표준 입력으로 실시간 JSONL을 공급합니다. 파일은 `--input 관측파일.jsonl`로 지정할 수 있으나 오래된 데이터는 실시간 API에서 거부합니다. 전송 결과의 각 `accepted`와 `reason`을 확인해야 합니다. HTTP 200 자체가 관측 수락을 뜻하지 않습니다.

## 5. 기록된 실측 파일로 지도 만들기

```powershell
.\.venv\Scripts\python -m mapping.build_recording --config config/my_mapping.json --input recordings/measurements.jsonl --output-dir data/maps
```

이 명령은 입력 파일을 새로 만들거나 센서를 구동하지 않습니다. 사용자가 수집한 파일을 읽고 기록 시각을 기준으로 유효성·동기화·중복을 검증합니다. 출처를 `recorded`로 표시하고 지도 ID를 출력합니다. 시간 기준을 현재 시각으로 위조하지 않습니다. 시뮬레이션 파일을 입력했다면 결과를 실측 지도라고 부르면 안 됩니다.

출력된 ID를 웹 화면의 ‘ID로 불러오기’에 입력합니다. 결과는 입력 좌표계와 보정에 의존하며, 이 도구 자체가 SLAM이나 위치 추정을 수행하지 않습니다.

## 6. 점유 갱신 방식과 한계

- 센서 장착 변환 → 로봇 자세 변환 → 지도 격자 순서로 계산합니다.
- 거리 오차와 위치 표준편차로 반사 띠 두께를 늘리고, 감지각과 방향 표준편차로 각도 범위를 늘립니다.
- 반사 띠의 여러 셀에 약한 양의 log-odds 증거를 분산합니다. 초음파가 정확한 한 점을 관측했다고 가정하지 않습니다.
- 이 역센서 모델은 경험적 초기 모델이며 보정된 확률 모델이 아닙니다. 반복 관측의 상관관계나 다중 반사까지 해결하지 못해 호 형태의 허상이나 과도한 확신이 남을 수 있습니다.
- log-odds는 -4~4로 제한합니다. 표시는 35% 이하 자유, 65% 이상 점유, 중간은 불확실입니다. 미관측 데이터는 -1입니다.
- 자유 공간 갱신은 기본 비활성입니다. `enable_free_updates:true`를 검증 후 적용하면 명목 빔 중앙 절반 영역에만 약한 자유 증거를 반영합니다. 무응답은 이 설정과 무관하게 갱신하지 않습니다. 이는 인증된 충돌 안전 영역이 아닙니다.
- 위치 실패, 과도한 오차, 좌표계 불일치, 오래된/미래/비동기/중복 측정은 갱신하지 않습니다.
- 관측 API는 이동 모터나 기존 Mock 상태에 영향을 주지 않습니다. 원본 점유 지도의 `usable_for_navigation`은 항상 false입니다. 모의 주행용 지도는 아래 절차로 별도 생성합니다.

## 7. 저장 및 검증

`POST /api/mapping/save` → 무작위 지도 ID 반환. `POST /api/mapping/load/{map_id}` → 불러오기. JSON 파일은 `data/maps/`에 원자적으로 저장하며 Git에서 제외합니다. log-odds, 관측 여부, 설정, 입력 출처, 마지막 센서 시각을 저장합니다. 불러오기 후 실시간 위치, 최근 반사, 궤적, 수락/거부 수치는 새 세션에서 다시 누적됩니다. 실시간 API는 수집 원본을 자동 저장하지 않으므로 재현 실험을 위해 수집기에서 JSONL을 별도로 보관합니다.

### 저장한 관측 지도로 모의 주행

1. **실측 관측**에서 수집 결과를 확인하고 **관측 지도 저장 → 주행 설정에서 불러오기**를 누릅니다. 주행 설정의 **관측 지도를 주행 지도에 등록**에서 기존 저장 ID를 직접 입력할 수도 있습니다.
2. 추가 여유를 미터로 입력하고 **불러와 미리보기**를 누릅니다. 20 × 20cm 차체의 반대각선 약 14.1cm에 추가 여유를 더하고, 격자 단위로 올림해 정사각형 범위에 적용합니다. 자유 증거는 점유 추정값 35% 이하인 관측 셀에서 가져옵니다. 미관측·불확실·점유 셀과 지도 바깥은 통행을 차단합니다.
3. 지도를 누르거나 X·Y 좌표(m)를 입력해 시작점과 이름이 있는 목적지를 지정합니다. 시작점은 지정한 좌표에, 목적지는 선택한 좌표가 속한 통행 칸의 중심에 등록됩니다. 초기 방향각을 입력한 뒤 **이 지도로 모의 주행 준비**를 누릅니다. 서버가 저장 원본을 다시 변환하고 시작점에서 모든 목적지에 연결되는지 확인합니다. 등록한 뒤에는 주행 설정에서 초기 위치·방향을 다시 지정하고, 목적지 버튼을 눌러 모의 이동하거나 주행 지도 JSON을 저장할 수 있습니다.

자유 공간 갱신의 기본값은 비활성입니다. 이 설정으로 수집한 저장 지도에 자유 증거가 없다면 변환해도 통행 가능한 칸이 생기지 않습니다. 실측으로 검증한 설정과 충분한 누적 증거가 필요합니다. 이 변환은 모의 경로 검토용이며, 실제 주행에는 독립적인 위치 추정과 현장 안전 검증이 필요합니다.

탐색·주행 화면의 방향각은 지도 위쪽(+Y) 0°에서 시계방향으로 표시합니다. 외부 수집기는 기존 계약대로 +X 기준, 반시계방향 라디안으로 `yaw_rad`를 보내세요.

검증 명령:

```powershell
.\.venv\Scripts\python -m unittest discover -s tests -v
```

이번 단계에서 좌표 변환, 불확실성 영역, 시간 검증, 무응답, 중복, 범위 초과, 저장 복원, API 및 기존 기능을 포함해 27개 테스트가 통과했습니다. 입력은 합성 테스트 데이터이며 실제 장비 정확도와 자유 공간 모델은 현장 검증이 남아 있습니다.

실제 연결에 필요한 다음 자료: ESP32 출력 예시, 시리얼 전송 속도/장치 경로, 센서 장착 실측값, 카메라/ArUco 또는 오도메트리 위치 출력 형식. 확인 전 포트·GPIO·Echo 배선은 지정하지 않습니다.
