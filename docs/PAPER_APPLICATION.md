# 논문 기반 적용: 자연어 의도와 근거 있는 상태 설명

참고: 채송화·성다훈·임유진, 「자율 이동 로봇 연구에서의 강화학습 및 대형 언어 모델의 적용 가능성 탐색」, ASK 2025, pp. 622–625. 사용자 제공 PDF를 검토했습니다. 이 문헌은 관련 연구와 결합 가능성을 논의하며, JETANK용 구현이나 실험 결과를 제공하지 않습니다.

## 이번 단계

논문 4절의 자연어 목표 설정과 행동 설명 방향을 참고해 다음을 구현했습니다. 아래 구현 방식은 이 프로젝트에서 설계한 것이며 논문의 알고리즘을 재현한 것은 아닙니다.

1. `ai/command_parser.py`에서 의도·목적지만 추출합니다. 외부 LLM 호출은 아직 없습니다.
2. `validate_intent`는 허용된 필드와 의도, 등록된 목적지를 검사합니다. 추가 속도 필드나 잘못된 목적지는 거부합니다. 향후 LLM 결과도 `RobotService.execute_intent`를 통해 동일 검증을 거쳐야 합니다.
3. 이동 전 모의 위치 추정 상태와 모의 장애 조건을 검사합니다. 주행 중 조건이 바뀌면 정지하고 목표를 해제합니다. 조건 복원만으로 재출발하지 않습니다.
4. 시작·정지·도착·조건 변경·명령 거부 이벤트에 순번, UTC 시각, 위치, 목표, 모의 조건을 기록합니다. 기록은 최근 100개이며 메모리에만 보관됩니다.
5. 상태 설명은 상태와 관련 주행 이벤트로 생성합니다. 거부된 명령이 실제 정지 원인을 덮어쓰지 않습니다. 설명 API 결과는 근거 이벤트 ID를 포함합니다.

## 수동 확인 시나리오

- A로 이동 → 모의 장애물 발생 → 즉시 정지 → B 이동 거부 → 상태 설명에 장애물 이유 확인.
- 모두 정상으로 복원 → 계속 정지 상태 확인 → B로 이동을 새로 입력해 재출발.
- 이동 중 모의 위치 추정 실패 → 정지, 지도상의 로봇 위치 표시 중단, 마지막 위치를 현재 위치로 안내하지 않는지 확인.
- `왜 멈췄어?`, `현재 상태 알려줘`로 설명 조회. 위치 조회와 정지 명령도 계속 사용 가능.

## API

`POST /api/mock/conditions`

```json
{"obstacle": true, "localization_valid": true}
```

두 필드는 모두 필수 boolean입니다. UI의 각 시험 버튼은 두 값을 함께 설정합니다. 이 API는 Mock 조건 주입용이며 센서 측정이나 실제 안전 제어가 아닙니다. 상태 조회에는 `conditions`, `events`, `explanation`, `planner`가 추가됩니다.

## 다음 단계

실측 지도·위치 추정과 A*를 먼저 구현한 뒤 장애물 발생 시 정지 → 지도 갱신 → 재계획을 연결합니다. 현재는 직선 이동 시뮬레이터이며 장애물 위치, 센서 유효 시간, 경로 가능 여부를 계산하지 않습니다. 강화학습·LLM 보상 설계·Sim-to-real은 후속 실험으로 둡니다. LLM의 자연어 설명을 추가하더라도 실제 기록에 없는 원인을 생성하거나 모터 제어를 수행하지 않도록 제한해야 합니다.
