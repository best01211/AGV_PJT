# JETANK 개발일지 — 보정 영상 기반 근거리 Depth 측정

> **작성일:** 2026년 11월 3일  
> **프로젝트:** 자연어 기반 Physical AI 자율주행 AGV  
> **오늘의 핵심:** 카메라 영상에서 실제 물체 거리를 측정하는 흐름을 개선하고, 기존 보정식의 한계를 확인한 뒤 Depth Pro를 실시간 파이프라인에 연결했다.  
> **현재 판정:** 거리 오차는 줄었지만, **1m 이내 ±1cm 요구는 아직 충족하지 못했다.**

## 1. 오늘의 목표와 측정 기준

장애물 회피와 물체 집기에 활용할 수 있도록, 카메라 영상에서 물체까지의 절대거리를 파악하는 것이 목표다. 오늘 작업은 그중 **Depth 추정·보정·측정·검증**에 집중했다.

| 항목 | 기준 |
| --- | --- |
| 입력 | 렌즈 왜곡을 보정한 JETANK 카메라 영상 |
| 측정 기준점 | 카메라 렌즈 중심 |
| 측정 물리량 | 렌즈 중심에서 물체까지의 직선거리 R |
| 요구 구간 | 1m 이내 |
| 허용 절대 오차 | ±1cm 이내 |
| 판단 방법 | 실측값과 동일 프레임·동일 물체 영역의 추정값 비교 |
| 현재 상태 | 전 구간 검증 미완료, 집기용 정확도 미확보 |

## 2. 작업 배경

실시간 카메라 영상과 Depth 화면은 연결되어 있었지만, 정면 물체의 거리가 실측과 크게 달랐다. 벽을 대상으로 만든 보정식이 다른 물체에서도 유효한지, 저장한 Depth 배열과 실측 기록이 정확히 대응하는지부터 확인했다.

사용자가 제공한 `CALIBRATION_NOTION.pdf`의 카메라 보정 내용을 기반으로 왜곡 보정을 적용했다. 다만 **렌즈 왜곡 보정과 절대거리 보정은 서로 다른 작업**이다. 렌즈 보정 오차가 작다는 이유만으로 Depth 거리까지 정확하다고 볼 수 없다.

### 카메라 보정 자료

| 항목 | 확인 내용 |
| --- | --- |
| 영상 크기 | 300 × 300 |
| 체커보드 내부 코너 | 14 × 9 |
| 촬영 / 보정에 사용한 이미지 | 38장 / 24장 |
| 보정 모델 | OpenCV pinhole, 왜곡 계수 5개 |
| 재투영 RMS | 약 0.334px |
| 현재 파라미터 출처 | PDF에 표시된 반올림 수치 |
| 한계 | 원본 보정 NPZ 미확보, 절대거리 정확도는 별도 검증 필요 |

```text
K = [[149.6753,   0,      147.9137],
     [  0,      199.2906, 154.0826],
     [  0,        0,        1     ]]

D = [-0.301191, 0.090162, -0.000561, -0.002133, -0.012141]
```

## 3. 오늘 진행한 내용

### 3-1. 실측 기록 저장 오류 개선

기존 화면에서는 기록 버튼을 누르는 사이 새 추론 결과가 도착하면, 화면에 보였던 결과가 최신 결과와 다르다는 이유로 저장이 거절될 수 있었다.

- 표시된 프레임을 일정 시간 보관하도록 개선했다.
- **표적 화면 고정 → 영역 선택 → 실측 입력 → 기록** 흐름을 추가했다.
- 고정한 프레임은 최대 2분 동안 사용할 수 있다.
- 원본 영상, 보정 영상, Depth 배열, 프레임 번호, 선택 영역을 함께 저장하도록 구성했다.
- 실측값이 없는 다운로드 NPZ를 다른 프레임의 실측값과 임의로 연결하지 않았다.

### 3-2. 벽 기반 보정식의 효과와 한계 검증

Depth Anything V2의 Small·Base·Large 및 입력 크기 294·518을 비교했다. 벽 중앙 영역에서는 Base 결과에 1차식을 적용하면 오차가 줄었지만, 새로운 물체에 일반화되지는 않았다.

기존 4개 벽 표본으로 만든 식을 고정하고, 추가 3개 표본으로 검사한 결과는 다음과 같다.

| 실측 거리 | 보정 후 거리 | 오차 |
| --- | --- | --- |
| 40cm | 34.6cm | -5.4cm |
| 70cm | 65.8cm | -4.2cm |
| 100cm | 94.3cm | -5.7cm |

평균 절대 오차는 약 **5.1cm**, 최대 절대 오차는 약 **5.7cm**였다.

이후 벽 7개 표본으로 만든 실험식은 다음과 같다.

```text
중앙 시험 보정값(m)
  = Base 원본 중앙값 × 0.5248586890 - 0.4192171250
```

이 식의 한 점 제외 교차검사에서는 평균 오차 약 5.1cm, 최대 오차 약 9.6cm가 나왔다. 같은 벽 장면의 중앙 영역에 근거한 식이므로, 물체 전체의 Depth나 새로운 장면에 그대로 적용할 수 없다. **최종 Depth Pro 파이프라인에는 이 벽 보정식을 적용하지 않는다.**

### 3-3. 물체 영역 ROI 측정 추가

화면 중앙만 측정하면 배경과 물체가 섞이거나, 사용자가 의도한 물체와 다른 부분을 기록할 수 있었다.

- 보정 영상에서 물체 내부를 드래그해 ROI를 지정하도록 했다.
- 모델은 전체 영상을 입력받고, 결과에서 선택한 ROI를 측정한다.
- ROI의 거리 중앙값과 10·90백분위 값을 확인할 수 있도록 했다.
- 기본 기록 모드를 ‘물체 영역’으로 변경했다.
- 벽 중앙 측정은 ‘기본 중앙 영역’을 명시적으로 선택해야 한다.

> ROI 내 값의 분산이 작다는 것은 출력이 균일하다는 뜻이다. 실측과의 오차가 작다는 보장은 아니다.

### 3-4. 광축 깊이 Z와 렌즈 직선거리 R 구분

사용자가 잰 거리는 **렌즈 중심부터 물체까지의 직선거리**였지만, 기존 비교에는 모델의 광축 방향 깊이 Z가 사용되고 있었다.

보정 후 내부 행렬 K′를 이용해 픽셀마다 다음과 같이 변환했다.

```text
X = (u - cx) / fx × Z
Y = (v - cy) / fy × Z
R = √(X² + Y² + Z²)
```

ROI의 각 픽셀에서 R을 계산한 후 중앙값을 구한다. 화면 가장자리에서는 Z와 R의 차이가 커질 수 있으므로 둘을 구분해 저장한다.

| 물체 | 실측 R | 기존 Base의 Z | 변환한 Base의 R |
| --- | --- | --- | --- |
| 핸드폰 | 21cm | 78.4cm | 90.0cm |
| 과자 포장지 | 43cm | 134.4cm | 139.2cm |
| 음료수 | 73cm | 177.1cm | 195.4cm |

프레임과 ROI는 기록과 일치했다. 물리량을 맞춘 뒤에도 큰 오차가 남아, 저장 오류나 Z/R 구분만으로 해결되는 문제는 아니었다.

### 3-5. 실측 단위 입력 오류 정정

최신 기록의 `0.06m`는 사용자 확인 결과 **60cm를 입력하려던 값**이었다.

- 실측값을 `0.60m`로 정정했다.
- 수정 전 CSV를 별도로 보존하고 정정 이력을 남겼다.
- 모델 출력과 원본 Depth 배열은 변경하지 않았다.
- m/cm 단위 선택과 환산 표시를 추가했다.

해당 60cm 기록에 기존 벽 보정식을 적용한 값은 약 80.8cm였다. 약 20.8cm 오차가 남아 기존 식의 일반화 한계를 다시 확인했다.

### 3-6. 실측 초점거리를 반영하는 Depth Pro 도입

벽 데이터를 반복해서 식에 맞추는 대신, 카메라 초점거리를 입력할 수 있는 **Apple Depth Pro**를 비교했다.

처리 흐름은 다음과 같다.

```text
JETANK 카메라 원본 영상 300×300
  ↓
K / D 기반 렌즈 왜곡 보정
  ↓
보정 후 fx / fy를 반영한 가상 영상 좌표 정규화
  ↓
변환된 영상에 대응하는 초점거리 입력
  ↓
Depth Pro로 광축 깊이 Z 추론
  ↓
보정 영상 좌표 300×300으로 복원
  ↓
K′로 렌즈 직선거리 R 계산
  ↓
선택 ROI의 거리 표시 및 실측 비교 기록
```

가상 영상의 크기는 399×300, 입력한 초점거리는 약 199.068px이다. 이는 영상 좌표 변환에 대응한 값이며, 카메라의 물리적 픽셀 구조를 새로 측정했다는 뜻은 아니다.

추론은 PC의 로컬 GPU에서 수행한다. 실시간 화면의 기본 Depth 엔진을 Depth Pro로 변경했고, 기존 벽 배율·오프셋은 추가하지 않았다.

## 4. 최종 비교 결과

동일한 저장 영상과 물체 ROI를 사용한 비교다. 기준은 모두 렌즈 직선거리 R이다.

| 물체 | 실측 | 기존 Base | Depth Pro | Depth Pro 절대 오차 | ±1cm 판정 |

| 핸드폰 | 21.0cm | 90.0cm | 25.3cm | 4.3cm | 미달 |
| 과자 포장지 | 43.0cm | 139.2cm | 42.9cm | 약 0.06cm | 해당 표본 통과 |
| 음료수 | 73.0cm | 195.4cm | 79.1cm | 6.1cm | 미달 |

| 지표 | Depth Pro 결과 |
| --- | --- |
| 평균 절대 오차 | 약 3.5cm |
| 최대 절대 오차 | 약 6.1cm |
| ±1cm를 만족한 표본 | 3개 중 1개 |
| 실측 표본 거리 범위 | 21~73cm |

초점거리를 모델이 추정하도록 맡긴 비교에서는 평균 오차가 약 42.5cm였다. 이번 자료에서는 알고 있는 카메라 파라미터를 반영하는 것이 효과적이었다.

> 이 세 표본은 모델 비교·선택에도 사용했다. 새로운 물체와 새로운 거리에서 얻은 독립 검증 성과가 아니며, 포장지 한 표본의 작은 오차를 전체 정확도로 해석할 수 없다.

## 6. 실행 및 측정 방법

프로젝트 폴더에서 실행한다.

```powershell
.\scripts\start-video.ps1
```

접속 주소: [실시간 영상 및 Depth 화면](http://127.0.0.1:8000/video)

1. 카메라 영상을 연결하고 Depth를 시작한다.
2. 측정할 물체를 화면에 놓고 **표적 화면 고정**을 누른다.
3. 왼쪽 보정 영상에서 배경이 섞이지 않도록 물체 내부를 드래그한다.
4. 렌즈 중심을 기준으로 동일한 표적 위치까지의 직선거리를 실측한다.
5. 대상 이름과 거리를 입력하고 m/cm 환산값을 확인한다.
6. 결과를 기록한다. 고정 후 2분이 지났으면 다시 고정한다.

기본 엔진 설정은 `JETANK_DEPTH_ENGINE=depthpro`다. 엔진을 바꾸려면 서버를 재시작해야 한다.

## 8. 검증 결과

- 웹·카메라·지도·거리 API 및 요구 판정 관련 테스트 **63개 통과**.
- 보정·후처리 테스트 **4개 통과**.
- 프런트엔드 Depth JavaScript 문법 검사 통과.
- 실제 GPU로 세 물체 표본에 대한 Depth Pro 비교 실행 완료.

**코드 테스트 통과와 실제 거리 정확도 통과는 별개다.** 현재 설정의 `full_range_verified`, `usable_for_grasp`는 모두 `false`다. 평균 오차가 작아도 개별 표본이 1cm를 초과하면 해당 시험 세트는 미달로 판정한다.

- [ ] 원본 카메라 보정 NPZ를 확보해 PDF 반올림 파라미터와 비교한다.
- [ ] 실제 사용할 최소 거리부터 1m까지 여러 거리에서 동일 물체를 반복 촬영한다.
- [ ] 각 거리에서 서로 다른 물체·화면 위치·조명 조건의 오차를 기록한다.
- [ ] 렌즈 기준 실측점과 ROI가 가리키는 물체 표면을 일치시킨다.
- [ ] 보정에 사용할 자료와 최종 평가용 자료를 분리한다.
- [ ] 별도 평가 자료에서 모든 표본의 절대 오차가 1cm 이내인지 확인한다.
- [ ] 고정 거리에서 반복 측정한 흔들림과 움직이는 장면의 지연을 확인한다.
- [ ] 기준 미달 원인을 분석한 뒤 추가 보정·기하학적 기준 또는 Depth 센서 사용 필요성을 판단한다.

## 10. 오늘의 결론

보정 영상·초점거리·측정 좌표·실측 기록을 일관된 기준으로 연결했고, Depth Pro에서 기존 Base보다 실제 거리에 가까운 결과를 얻었다. 다만 확인된 최대 오차는 약 6.1cm이므로, 현재 상태를 **1m 이내 ±1cm 측정 완료** 또는 **집기에 충분한 Depth 확보**로 보고할 수는 없다.
