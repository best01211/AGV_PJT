# JETANK CSI 양안 보정과 Depth 거리 검증

**작업일** 2026-11-17

CSI 카메라 두 대로 직접 촬영한 ArUco 사진에서 양안 보정값을 계산해 웹에 적용했다. 이후 FoundationStereo의 계산 시간을 줄이고, 40·70·100cm 실측 기록으로 거리 배율을 보정했다. 배율 계산에서 제외해 둔 검증 3건의 평균 절대 오차는 **4.27cm에서 0.53cm**로 줄었다.

## 1. CSI 양안 캘리브레이션

- 보정판은 ArUco `DICT_6X6_50`의 ID 1~12를 4열×3행으로 배치했다. 마커 한 변은 **41.5mm**, 바깥쪽 마커 테두리 기준 배열 크기는 **192.5×144.5mm**로 사용했다.
- 웹에 **보정 사진 촬영** 버튼을 추가했다. 양쪽 카메라에서 마커 12개가 모두 검출되고 기존 사진과 보드 자세가 다를 때 좌우 JPEG를 저장한다.
- 저장한 **13쌍 중 12쌍**으로 보정값을 계산하고 **1쌍**을 검증에 남겼다. 해당 검증 사진에서 같은 마커 모서리의 세로 차이 95백분위는 **65.82px → 2.84px**였다. 양안 보정 재투영 RMS는 **0.82px**였다.
- 카메라는 480×270으로 촬영하며, 사진 저장과 Depth 웹 입력에는 640×480으로 리사이즈된 프레임을 사용했다. 새 보정값은 이 입력 크기에서 계산했다.

### 카메라 보정 파라미터

내부 행렬 `K = [[fx, 0, cx], [0, fy, cy], [0, 0, 1]]`의 값은 **640×480 입력의 픽셀 단위**다.

| 파라미터 | 왼쪽 CSI 0 | 오른쪽 CSI 1 |
| --- | ---: | ---: |
| `fx` | 508.473968 | 527.712378 |
| `fy` | 672.291878 | 698.055612 |
| `cx` | 351.762615 | 322.536502 |
| `cy` | 223.036598 | 169.714329 |
| 왜곡 `k1` | −0.398830059 | −0.347804495 |
| 왜곡 `k2` | +0.606877805 | +0.213115903 |
| 왜곡 `p1` | −0.000191926 | +0.000584346 |
| 왜곡 `p2` | −0.000592604 | +0.000254007 |
| 왜곡 `k3` | −1.143270269 | −0.216647993 |
| 카메라별 재투영 RMS | 0.708px | 0.826px |

왼쪽 카메라 좌표를 오른쪽 카메라 좌표로 변환할 때 `X_right = R × X_left + T`를 사용한다.

```text
R = [[ 0.999711475,  0.023018902, -0.006862783],
     [-0.023136656,  0.997977321, -0.017603249],
     [ 0.006454675,  0.017756951,  0.999821498]]

T = [-89.472098, +3.140593, +20.222413] mm
```

- 추정 카메라 간격 `‖T‖`은 **91.78mm**다. `T`의 세로 성분은 카메라 좌표계의 값이며, 지면 기준 장착 높이 차이는 별도로 측정해야 한다.
- 보정에 사용한 12쌍의 정렬 후 세로 차이 95백분위는 **2.16px**였다. 별도 검증 1쌍의 **65.82px → 2.84px**는 보정 파일을 검증할 때 사용한 `rectify_alpha=0` 기준이다. 웹에는 더 넓은 시야를 위해 `rectify_alpha=0.4`를 적용했다.
- 표와 행렬은 문서용으로 반올림했다. 코드에서 사용할 정밀도는 JSON에 저장되어 있다.

## 2. 실시간 웹 비교 화면

- 같은 프레임의 좌우 원본과 정렬 영상을 한 화면에서 비교할 수 있게 했다. 네 영상은 Depth 계산과 별도로 갱신한다. 영상 연결이 끊기면 마지막 프레임을 지우고 다시 연결을 시도한다.
- 정렬 영상이 크게 확대되던 문제는 `rectify_alpha=0.4`로 시야를 넓혀 완화했다. 미리보기에서는 두 영상에 공통으로 유효한 영역 **640×363**만 표시해 검은 가장자리를 없앴다. 화면에서 클릭한 위치는 전체 정렬 영상의 좌표로 환산한다.
- **세로 이동만 보기**에서는 왼쪽 영상만 **−62px** 위로 옮기고 좌우를 같은 **640×480** 크기로 표시한다. 이동으로 비는 부분은 회색으로 표시하며, 화면에서 값을 조절할 수 있다. 거리 계산은 CSI 양안 정렬을 사용한다. [세로 이동 비교 화면](http://127.0.0.1:8003/?vertical=-62)
- 왼쪽 카메라가 같은 프레임을 반복 전송한 경우에는 CSI 0만 재시작했다. 이후 연속 5쌍에서 좌우 프레임이 모두 갱신되는 것을 확인했다. Jupyter 커널 시작이 실패한 경우에는 호스트에서 `jetbot_jupyter` 컨테이너를 재시작한 뒤 카메라와 웹 송출을 다시 실행했다.

## 3. FoundationStereo 처리 속도

- 모델 입력을 기존 **640×480에서 480×360**으로 줄이고 추론 반복을 **16회에서 8회**로 낮췄다. 시차를 원래 픽셀 단위로 환산한 뒤 보정값으로 거리를 계산한다.
- 같은 40cm 사진 3쌍에서 계산 시간 중앙값이 **1.58초 → 0.65초**로 줄었다. 변경 전후의 추정 거리 차이는 최대 **0.02cm**였으며, 한 사진의 유효 픽셀 비율은 약 **3.4%포인트** 낮아졌다.
- 여러 탭이 같은 지점의 Depth를 동시에 요청하면 진행 중인 계산 결과를 함께 사용한다. 실제 웹에서 동시 요청 3건이 계산 결과 1건을 공유했고, 그 확인에서 영상 수신과 계산을 합쳐 **2.19초**가 걸렸다.

## 4. 거리 배율 보정과 실측 검증

실측 기록 **14건** 중 절대 오차가 **30cm를 초과한 3건**과 **측정 불가 1건**을 배율 계산에서 제외했다. 모두 실측 70cm에서 발생했다. 오차 초과 3건의 추정값은 약 **105.5~106.2cm**였다.

유효한 사진 10쌍을 빠른 FoundationStereo 설정으로 다시 계산했다. 7쌍에서 `실측 거리 ÷ 배율 적용 전 추정 거리`의 중앙값을 구해 **0.9478587132094086**을 웹에 적용했다. 직선거리와 광축 깊이 Z는 모두 같은 배율을 사용한다. 각 거리에서 마지막 유효 기록 한 건씩을 남겨 배율을 검증했다.

웹에서 표시하는 거리는 선택한 점 주변 **21×21픽셀** 중 유효한 값의 중앙값이다. 유효 픽셀이 **50% 미만**이면 `측정 불가`를 표시한다. 줄자 실측은 왼쪽 렌즈 중심에서 선택한 표면 지점까지의 직선거리를 기준으로 했다.

| 실측 거리 | 배율 적용 전 | 배율 적용 후 | 적용 후 오차 |
| --- | ---: | ---: | ---: |
| 40cm | 41.99cm | 39.80cm | −0.20cm |
| 70cm | 74.67cm | 70.77cm | +0.77cm |
| 100cm | 106.15cm | 100.61cm | +0.61cm |

검증 3건의 평균 절대 오차는 **4.27cm → 0.53cm**였고, 실제 카메라의 웹 응답에서도 새 배율이 적용된 것을 확인했다. 이 검증은 유효 기록을 재계산한 결과이며, **70cm 7건 중 오측정 또는 측정 불가가 4건** 발생한 문제는 남아 있다.
