# JETANK 자율주행 관제 · Mock MVP

## 실행

Python 3.10 이상, 터미널의 현재 디렉터리를 이 프로젝트 루트로 설정합니다.

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
$env:JETANK_MODE = 'mock'
.\.venv\Scripts\python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

브라우저에서 http://127.0.0.1:8000 을 엽니다.

1. **지도 만들기**에서 빈 격자에 시작점, 이름이 있는 목적지, 장애물을 표시하고 **이 지도로 시작**을 누릅니다. 제공받은 JSON 파일이 있다면 **지도 불러오기**를 사용합니다.
2. 지도를 등록하면 모의 로봇이 시작점에 표시되고 명령 입력이 활성화됩니다. 등록한 목적지 이름으로 `출고대로 가줘`와 같이 입력합니다.
3. 빠르게 시연하려면 **예제 지도 불러오기**를 누르고 `출고대로 가줘`를 입력합니다. **현재 지도 저장**으로 다시 불러올 수 있는 JSON 파일을 내려받습니다.

주행 지도 위의 **초기 위치·방향 설정**에서 시작점 마커를 끌거나, 지도를 누르거나, X·Y 좌표(m)를 입력해 시작 위치를 지정합니다. 지도 위쪽 기준의 시계방향 각도를 입력해 **초기 상태 적용**을 누릅니다. 값을 다시 사용하려면 **현재 지도 저장**으로 주행 지도 JSON을 내려받습니다.

API 문서는 `/docs`입니다.
프로젝트 소개 페이지는 http://127.0.0.1:8000/about/ 입니다. 제어 대시보드 상단 링크로도 열 수 있습니다. 독립 소스는 `sites/rove-intro/dist/`, 구성 및 검증 기록은 `docs/INTRO_PAGE.md`를 참고하세요.
AGV 탐색 관제는 http://127.0.0.1:8000/mapping 입니다. **탐색 재개**를 눌러 시뮬레이션에서 누적 관측과 주행 궤적을 확인하거나 **실측 관측**에서 외부 수집기의 관측 결과를 볼 수 있습니다. 실측 화면에서 **관측 지도 저장 → 주행 설정에서 불러오기**를 누르면 20 × 20cm AGV에 추가 여유 공간을 적용한 모의 주행 지도를 만들 수 있습니다. **예제 주행 지도 열기**는 별도로 제공됩니다. 실측 입력, 변환 조건 및 카메라 설정은 `docs/SENSOR_MAPPING.md`를 참고하세요.
실시간 카메라 화면은 http://127.0.0.1:8000/video 입니다. 확인된 영상 URL과 `JETANK_CAMERA_FORMAT`을 설정한 뒤 연결합니다. 지원 형식과 설정 방법은 `docs/CAMERA_CONNECTION.md`를 참고하세요.
2026-11-03 JETANK의 `http://70.12.231.81:8765/video` MJPEG 영상 수신을 확인했습니다. 기존 Jupyter 영상 서버가 실행 중이면 `.\scripts\start-video.ps1`로 확인된 설정을 적용해 시작할 수 있습니다.
같은 `/video` 화면에서 **Depth 시작**으로 PDF의 300×300 렌즈 보정과 Metric Depth 추론을 실행합니다. 별도 GPU 실행 환경을 사용하며 거리 정확도는 미검증입니다. 설정·실측 비교·한계는 `docs/DEPTH_INTEGRATION.md`를 참고하세요.
현재 실시간 모델은 **Base 294**이며, 7개 나무색 벽 실측점의 중앙 다점 보정값을 원본값과 함께 표시합니다. 집기 정확도는 미검증입니다. 적용 범위와 새 기록 형식은 `docs/DEPTH_RUNTIME_CORRECTION.md`에 있습니다.
실제 정면 물체는 `/video`에서 **표적 화면 고정 → 보정 영상에서 물체 영역 드래그**로 선택해 측정·기록할 수 있습니다. 벽 보정식을 물체에 적용하지 않습니다. `docs/TARGET_DEPTH_MEASUREMENT.md`를 참고하세요.
최신 실시간 후보는 **Depth Pro + 렌즈 보정 + 실측 초점거리**입니다. 목표는 1m 이내 ±1cm이며, 현재 세 표본의 평균/최대 오차 약 3.5/6.1cm로 미달입니다. `docs/NEARFIELD_DEPTH.md`가 최신 설정과 한계의 기준입니다.
모바일 테스트는 신뢰하는 로컬 네트워크에서만 `--host 0.0.0.0`으로 실행하고 PC의 실제 IP:8000으로 접속합니다. 현재 인증이 없으므로 외부에 공개하지 않습니다.
`.env.example`은 설정 항목 참고용이며 `.env` 자동 로딩은 구현하지 않았습니다. PowerShell 환경변수로 지정합니다. `JETANK_MODE`가 mock 이외의 값이면 서버는 시작을 거부합니다.

## 구현 내용

- 반응형 대시보드, 백엔드 연결 상태, 주행 상태, 모의 위치
- 사전 제작 지도 불러오기, 지도에 등록된 장소로 한국어 이동 명령, 정지와 상태·위치 조회
- 명령 해석 결과와 최근 50개 기록, 주행 중 약 0.1초 간격 상태 조회
- 상하좌우 A* 경로 계산, 직선 주행과 제자리 회전, 경로가 없을 때 명령 거부
- 센서·RGB·Depth 연결 대기 표시
- 의도/목적지 허용 목록 검증, 근거 이벤트가 있는 상태 설명
- Mock 장애물·위치 추정 실패 시험 및 자동 재출발 방지

논문 기반 적용 범위와 시험 방법은 `docs/PAPER_APPLICATION.md`에 정리했습니다.

서버는 단일 로봇 상태를 공유합니다. 여러 사용자의 명령은 마지막 수락 명령을 따릅니다. 서버 재시작 시 초기화되므로 단일 worker로 실행합니다. 표시되는 정지는 모의 주행 정지이며 실제 비상 정지 장치가 아닙니다.

```powershell
.\.venv\Scripts\python -m pip install -r requirements-dev.txt
.\.venv\Scripts\python -m unittest discover -s tests -v
```

API: `GET /api/state`, `POST /api/commands` (JSON `{"text":"A 지점으로 이동해 줘"}`), `POST /api/stop`.
명령은 1~200자이며 해석할 수 없는 명령은 HTTP 200 응답의 `accepted: false`로 반환합니다. 요청 형식 오류는 422입니다.

## 지도 전달 형식

지도 담당 조는 [예제 지도](frontend/navigation-demo.json)와 같은 JSON을 전달합니다. UI에서 파일을 선택하거나 `PUT /api/navigation/map`에 JSON을 보내 등록합니다. 등록한 지도와 모의 위치는 서버 메모리에 저장됩니다. 유효한 새 지도를 등록하면 진행 중인 경로가 취소되고 새 시작점으로 초기화됩니다. 지도 등록 전에는 API도 이동 명령을 `map_required`로 거부합니다.

- `schema_version`은 1입니다. `frame_id`는 지도 좌표계 이름이고 `resolution_m`은 한 칸의 크기(m)입니다. `origin_x_m`, `origin_y_m`은 좌하단 원점(m)이며 생략 시 각각 0입니다.
- `cols`, `rows`는 칸 수입니다. `data`는 총 40,000칸 이하의 1차원 배열이며, 좌하단부터 한 행씩 왼쪽에서 오른쪽으로 저장합니다. 0은 통행 가능, -1은 미확인, 1~100은 통행 차단입니다. 제공자가 실제 통행 가능 여부를 판정해 0으로 표시합니다.
- `start`와 `destinations`의 위치는 0부터 시작하는 `[열, 행]`입니다. 선택 필드 `start_position_m`에 시작 칸 내부의 정확한 `[X, Y]` 좌표를 미터로 저장할 수 있습니다. 이 필드를 생략하면 시작 칸의 중심에서 출발합니다. 일반 목적지는 칸 중심의 미터 좌표를 사용합니다. 장소 이름에는 한글, 영문, 숫자, 공백을 사용할 수 있습니다.
- `start_heading_deg`는 지도 위쪽 0°에서 시계방향으로 설정한 정수 방향각(0~359°)입니다. 이전 지도에서 이 필드를 생략하면 오른쪽 90°로 시작합니다.
- 모의 주행은 20 × 20cm 차체의 회전 반경 약 14.1cm를 기준으로 장애물과 지도 경계에 여유를 확보합니다. 화면 방향각은 지도 위쪽부터 시계방향으로 0°·90°·180°·270°입니다. 기존 API의 `heading_rad`와 센서 입력 `yaw_rad`는 +X 기준 반시계방향을 사용합니다.
- `로봇아, 출고대까지 가 줄래?`, `검사 구역 먼저 들르고 출고대에 가 주세요`, `검사구역, 출고대, 충전소 순으로 방문해줘`처럼 입력할 수 있습니다. 순서 방문은 최대 10곳까지 지정할 수 있습니다. `충전하러 가줘`는 지도에 등록된 충전소로 이동합니다.
- `그만 가!`로 정지하고, `지금 어디쯤이야?`, `왜 멈춰 있어?`, `어디로 갈 수 있어?`로 위치·상태·목적지를 조회할 수 있습니다. `출고대까지 얼마나 걸려?`는 현재 위치에서 해당 장소까지의 거리와 모의 주행 시간을, `얼마나 남았어?`는 진행 중인 경로의 남은 거리와 시간을 표시합니다.

모의 로봇은 지도에서 상하좌우로 연결된 경로를 따라 직진하고, 방향을 바꿀 때는 제자리에서 회전합니다. 예상 소요 시간에는 직선 이동, 회전, 경유지 대기가 포함됩니다. 실기 주행에는 동일 지도 좌표계의 실시간 위치, 로봇 외형과 여유 공간을 반영한 통행 가능 영역, 회전·가감속을 반영한 경로 추종, JETANK 주행·정지 인터페이스가 필요합니다. 현장 연동 항목은 `docs/HARDWARE_INTEGRATION.md`에 있습니다.

## 파일 구조

- `backend/main.py`: FastAPI 라우트, 상태 갱신 루프, 정적 파일 제공
- `backend/service.py`: 독립적인 명령 파서, 잠금으로 보호된 Mock 상태
- `frontend/`: HTML/CSS/JavaScript 대시보드
- `tests/test_service.py`: 명령, 정지, 도착 검증
- `docs/PROJECT_PLAN.md`: 초기 분석, 미구현 목록, 개발 일정
- `docs/HARDWARE_INTEGRATION.md`: 실제 로봇 연동 확인사항

실제 카메라/Depth Anything 코드가 작업 폴더에 없으므로 기존 구동을 검증하거나 통합하지 않았습니다. 실제 모터 호출, GPIO 설정, 네트워크 탐색은 수행하지 않습니다.
